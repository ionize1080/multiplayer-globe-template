# Satellite exploration and IONACS sign-in

The public rotating globe remains available without signing in. Its real sunlight mode displays the approximately 23.44 degree axial tilt, a cyan polar axis and the current UTC time. The geographic sun vector is transformed with the display rotation, preserving the current geographic day/night boundary as the globe turns. The solar approximation follows https://aa.usno.navy.mil/faq/sun_approx; this is a visualization, not a navigation ephemeris.

Free exploration requires an existing IONACS mailbox identity. `/auth/login` creates a 10-minute, Secure/HttpOnly host-only state cookie and redirects to `ionacs.com`. The navigation app performs its existing password and Turnstile checks. It returns a 120-second, single-use code with a fixed `https://ionize.club/auth/callback` destination. The callback checks browser state before atomically consuming the code. The resulting host-only session lasts 24 hours and is checked against the original navigation session and mailbox password version on each protected request. Navigation logout and password changes revoke access. Logout requires a same-origin POST. No mailbox password is submitted to this application.

## Release order

1. In `ionize1080/ionacs-navigation`, deploy through the existing `npm run deploy` workflow. It applies additive migration `0004_globe_sso.sql` and releases the authorization endpoint and login continuation.
2. Verify the existing Worker account, domain and deployment settings before deploying this repository. `wrangler.json` adds the `MAIL_DB` binding to the same existing `maildata` D1 database. It does not create a mailbox or change a password.
3. Before deploying the immersive explorer update, apply the additive shared-cache schema with `npx wrangler d1 execute MAIL_DB --remote --file migrations/0001_weather_cache.sql`. This creates only globe weather tables; existing mailbox data is unchanged.
4. Run `npm ci`, `npm test`, `npm run check`, then the existing authorized `npm run deploy` workflow. The build copies Cesium's worker/assets locally and splits the explorer into a lazy-loaded module.
5. Verify a real login, return to exploration, logout and unauthenticated `/api/globe/weather` rejection on production. Do not seed local test identities in the production database. The preview configuration uses a placeholder isolated database and cannot perform production SSO.

## Data and limits

- CesiumJS renders Esri World Imagery with its provider attribution. No Google API or Google billing account is used. The data provider's terms and availability still apply. Imagery is archival, not live, and coverage/resolution varies. Zoom is bounded by available imagery (level 19) and a 100 m camera-height floor; it is not infinite detail. Terrain overlays and point heights are available, but these do not displace the globe into 3D mountains or provide photorealistic buildings.
- Cloud imagery reuses EUMETSAT / Live Cloud Maps, with publication cadence around three hours. Publication time is not observation time. Some polar coverage is absent. Existing public decorative/overview clouds are unchanged.
- Temperature and 10 m wind use Open-Meteo current model data. A fixed 264-point, 15-degree global grid is shared across users and regions in D1 for three hours; browsers check the overview every 15 minutes. Closer views additionally request aligned regional tiles. Color interpolation is visual only. Wind arrows show downwind direction, using vector-component interpolation. The displayed timestamp is the model-valid time, not fetch time. With any weather layer enabled, clicking queries Open-Meteo separately for that location using its available local model. Ten current parameters are returned, including apparent temperature, humidity, gusts, pressure and precipitation. Model cell coordinates and valid time are displayed. Coordinates are rounded to 0.01 degrees for a shared 30-minute cache; this does not imply 0.01-degree source resolution. This first version does not supply street-level weather, a forecast time slider or animated wind particles.
- Open-Meteo's free endpoint is for non-commercial use and has request limits: https://open-meteo.com/en/pricing . Multiple locations count toward usage. Shared D1 counters cap explorer upstream usage at 550/minute, 4,400/hour and 8,000/day, counting every location in a grid request. Point-query cache misses additionally cap each signed-in user at 10/minute and 400/day. Cache hits are reused across users, and an atomic refresh lease prevents concurrent duplicate fetches. These budgets cover explorer requests, not unrelated clients of the same provider. Signing in and caching do not remove the free endpoint’s non-commercial restriction.

## Validation

`npm test` includes actual local D1 tests for mismatched state, concurrent code replay, anonymous access, cross-origin logout, navigation-session revocation and mailbox password changes, plus solar-solstice and rotation-invariance checks. Navigation has a separate test for guest redirection and fixed callback enforcement. Browser previews must use isolated synthetic identities only.

## Immersive layout and reference layers

Exploration fills the viewport and hides clocks, markets and rotation controls. The exit button or Escape restores the rotating dashboard. Weather details reserve a 340 px desktop column or a separate bottom region on narrow screens; the map resizes and recenters the selected location instead of putting a card over it.

Clouds, temperature, wind arrows, geographic features and place labels have independent switches. When temperature and wind are both enabled, the color field shows temperature and arrow color shows wind speed. Natural Earth v5.1.2 supplies public-domain country-level reference boundary lines (1:50m) and city labels, bundled as small static assets. Closer views load 20-degree spatial chunks containing 1:10-million country and province/state lines, city and province labels. Chinese names are preferred where available. Labels are filtered by scale, deduplicated and checked for screen-space collisions. These are generalized reference data, not street labels or cadastral boundaries. Satellite imagery remains provider-hosted.

All map positions use WGS84. Natural Earth vectors use WGS84 longitude/latitude directly; Esri imagery uses the WGS84 Web Mercator system. No GCJ-02 or BD-09 offsets are applied. Adding a domestic offset map provider later requires explicit datum conversion at its boundary. Reference boundaries reflect the source dataset and are not a bespoke authoritative boundary product.

Current cache payloads are small JSON records with expired-row cleanup. AWS or Oracle storage can be considered if a future release stores high-resolution weather rasters; neither service is provisioned or required by this release.

Weather cache tests use actual isolated D1 storage and cover shared reuse, concurrent refresh exclusion, provider budget rejection and coordinate validation.

## Adaptive weather and finer rendering

The `/api/globe/tile?level=L&x=X&y=Y` endpoint requires the same IONACS session as other explorer APIs. Tile IDs and ranges are strictly validated before any upstream request. WGS84 sampling steps are 5°, 2.5°, 1°, 0.5°, 0.25°, 0.1°, 0.05° and 0.025°. Each fixed tile contains 5×5 query points; the viewport planner chooses the finest level covering the view with at most six tiles. This is at most 150 uncached query locations per settled view, not a claim of 0.025° model resolution. Open-Meteo best_match and nearest cell selection provide available model detail.

Reference names now use separate `*.places.json` assets, so enabling labels alone never fetches or builds boundary geometry. Three regional chunks can load concurrently, labels appear before lines, and the viewer retains up to eight recently used geometry chunks (or the current visible set if larger), plus 24 decoded payloads. Switch-off visibility is immediate; camera-settled label layout uses a 150 ms debounce. Boundary polylines follow the current ellipsoid directly, avoiding ground-clamping work while the explorer has no displaced 3D terrain. If 3D terrain is added, revisit this geometry choice.

Regional JSON is shared in D1 for one hour, with refresh leases and up to six-hour labelled stale fallback on upstream errors or quota exhaustion. Regional requests consume the same global 550/minute, 4,400/hour, 8,000/day budget as the overview and point APIs; each viewer additionally gets 300 regional sample locations/minute and 1,600/day. A 25-location batch costs 25 units. Quota accounting is conservative: failed upstream attempts and partially admitted multi-budget reservations can consume quota without obtaining data. Cache hits do not consume provider quota.

Camera motion is debounced by 900 ms, refresh starts are at least five seconds apart, and at most two regional requests per browser explorer run concurrently. Completed superseded requests may populate the browser cache but cannot overwrite the current view. Browser regional cache is bounded to 96 tiles. Missing detail falls back to the coarse overview or transparent missing data, with status shown. Periodic retry is once per minute; 429 sets a one-minute client cooldown.

Weather rasters are generated on the client at up to 1536×1024 pixels for the current view, with a continuous temperature palette and subtle 5°C contours. Wind arrows are sampled from interpolated east/north components, not interpolated bearing angles. Rendering yields between row groups and abandons obsolete results. All temperatures remain model estimates. Clouds have a separate 0–100% overlay-strength slider; it changes alpha only, not physical thickness, source resolution, or observation frequency.

Run `node scripts/build-reference-data.mjs` to reproduce the version-pinned Natural Earth spatial chunks (about 11.2 MB combined, not downloaded in full by each user). Assets are served directly by Workers static hosting. Dynamic weather payloads and quotas remain in D1; no AWS or Oracle resources are created. Tests include tile validation, antimeridian and polar coverage, budget bounds, vector interpolation, actual D1 cache reuse and bounded stale responses.

## Native air temperatures and lake artifacts

Point, global and regional Open-Meteo requests now use `cell_selection=nearest&elevation=nan`. The latter disables extra elevation lapse-rate downscaling. On 2026-11-03 a lake at 31.7873 N, 89.1181 E returned model elevation 0 m but default elevation 4545 m: the default correction changed 1.8°C to -27.8°C. Qinghai Lake similarly changed 3.8°C to -17°C at 3195 m. These observations demonstrate a provider correction artifact, not water temperatures. Disabling downscaling also loses useful elevation adjustment on mountainous land; readings are now explicitly native model-cell air temperatures, not a promise of locally measured conditions. The grid sampling resolution remains independent of the model's native resolution.

Point pressure is `pressure_msl`, labelled sea-level pressure, because unadjusted surface pressure at an erroneous model elevation is not local ground pressure. Old shared cache entries are bypassed with native-versioned keys; browser weather endpoints use `v=2`. All interfaces say air at 2 m, not water temperature. Lake surface temperature is not supplied.

For multi-location requests, Open-Meteo requires an `elevation` array with the same length as latitude/longitude arrays. Each location therefore receives a `nan` entry. Regression tests cover both 25-point regional and 264-point global requests; a single `nan` for a batch returns HTTP 400.

## Free terrain overlays and elevation details

Mapzen Terrain Tiles (Terrarium) provide independent elevation coloring, fixed-light hillshade and contours. These are raster overlays; no API key, paid subscription, Cesium ion terrain, or Google account is required. Data credits and coverage limitations are at `/data/terrain-attribution.html`. Sources include SRTM, 3DEP, EU-DEM, regional higher-resolution DEMs and coarse ETOPO1 bathymetry. SRTM is sampled around 30 m but the source documentation describes 90 m nominal quality; source detail varies widely. This ready-tiled source avoids maintaining a global raw Copernicus GeoTIFF processing pipeline. It is not a claim to provide the highest possible free DEM resolution everywhere.

`/api/globe/terrain/{z}/{x}/{y}.png` requires the existing IONACS session. Strict XYZ validation caps zoom at 14 and prevents arbitrary proxy URLs. Fetches use one fixed public upstream and stream PNG responses. Cloudflare upstream fetch caching requests a 30-day TTL on success (subject to normal edge eviction), 60 seconds for 404 and zero for upstream 5xx. Browser responses are private with a one-day TTL; no terrain blobs enter D1. Authentication still runs on each server request. Client DEM memory is a 96-tile LRU (about 24 MiB), four network requests at once, with duplicate in-flight coalescing. Adjacent tiles share one-pixel contour/gradient borders. Layer toggles share the decoded cache; the imagery engine requests only visible tiles and progressive detail.

The browser decodes signed Terrarium heights without color conversion, excludes no-data values and generates contours using interpolated cell crossings. Contours appear at regional scales and intervals decrease from 500 m at level 5 to 20 m at levels 13–14; index contours are five times the interval. Fine sampling/contour spacing does not increase source measurement accuracy. Hillshade is fixed NW illumination, not actual sunlight. The UI has a collapsible layer menu and an independent terrain strength slider. Existing weather and reference layers may be enabled simultaneously.

Every selected weather/terrain point queries a level-14 terrain sample independently of weather. Elevation is rounded to whole metres and explained as a DEM estimate. Negative heights are retained: they may represent bathymetry or below-sea-level land and are not automatically called water depth. Water areas are not treated as real-time water-surface measurements. Horizontal coordinates are WGS84/Web Mercator without GCJ-02/BD-09 offsets; vertical reference and accuracy depend on the source DEM, and coverage stops near ±85.05°. Heights do not alter air temperatures.

Browser validation on 2026-11-03 used actual Chromium rendering at 1280×720 and 390×844, with an isolated local synthetic login and real upstream data. Checks covered all eight overlays, regional zoom/pan, removing layers, provincial boundaries, label completeness and a separate mobile detail area. The Tibetan screenshot location returned 4539 m and 1.9°C; a Dianchi sample returned 1886 m. The global request returned 264 valid temperature points and regional overlays completed. A province-label depth occlusion bug found in browser testing was fixed; globe-side visibility and collision layout update while moving. Label-only Kunming-region payload is 50,165 bytes versus 534,474 bytes for the combined chunk. These are payload sizes, not a network-latency or hardware-FPS benchmark. Cold weather detail can take several seconds; retained data stays visible while refreshing.

## Satellite time studio (2026-11-04)

The existing latest / least-cloudy-in-30-days single-image flows remain the default. A direct “卫星时光” exploration tab opens the studio, with separate animation and timestamp-browser modes. Browse queries a UTC calendar month, returns at most ten text-only observations per page and never invokes the image processing API until a timestamp is selected.

`/api/globe/satellite/timeline` shares the existing authentication, bounded viewport, metadata cache, render manifests and image proxy. Catalogue pages are cached separately for 15 minutes; each query is bounded to 24 upstream pages of 100 records, with a 60-second total deadline and a 25-second per-page deadline. Excessively dense catalogues fail explicitly rather than silently claiming a complete latest sequence. Recent sequences start with a year of history and expand backwards when needed (earliest search: 2017); periodic sequences use calendar offsets from the current UTC day, including month-end clamping. Weekly/monthly/quarterly tolerances are ±3.5/15/45 days. Timestamps are deduplicated; missing slots are skipped without blank placeholder frames and actual offsets are displayed.

Animation defaults to 15 frames and 1 frame/second; counts are 5–30 in steps of 5 and speeds are 0.25/0.5/1/2/4 frames per second. It loops chronologically, supports pause, stepping and scrubbing, and pauses on camera movement and document hiding. The old displayed image remains until the next is rendered. Loading can slow playback below the requested rate. Frames use at most 512 px on their longest side; single observations retain up to 1024 px. The client coalesces in-flight downloads, prefetches only the next frame, and retains up to 32 decoded images or an estimated 48 MiB, plus at most three GPU layers during replacement. Disabling the mode aborts requests and releases images. Cached loops incur no further image requests. To accommodate one bounded catalogue plus a 30-frame sequence, satellite burst budgets are 60 requests/user/minute and 90 globally/minute; daily 300 and monthly 8,000 request/processing-unit protections remain unchanged.

Validation covers UTC calendar arithmetic, gap skipping, no duplicate timestamps, tolerance boundaries, malformed inputs, catalogue pagination, shared D1 caching and no Process API usage while browsing. Browser QA uses isolated synthetic observations and genuine Cesium rendering, with no production session or test-account creation.


## Recovered production biodiversity features (2026-11-05)
